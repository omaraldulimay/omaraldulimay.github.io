Das Problem

Ein Marktplatz kassiert für viele Marken. Geld darf nie doppelt, nie halb und nie verloren gebucht werden.

  1. Kunde klickt zweimal auf Bezahlen
  2. Server stürzt mitten in der Buchung ab
  3. Bank und Buchhaltung zeigen andere Zahlen

Probier es selbst

Klick ruhig zweimal. Schieß den Server ab. Der Ledger bucht trotzdem jeden Cent genau einmal.

    Im Browser nachgebaut, mit denselben Regeln wie der echte Ledger: Idempotenz-Schlüssel, Transaktion mit Rollback, Summe immer 0. Der echte Code liegt auf GitHub.

    Der Bankabgleich

    Kontoauszug rein, Abweichungen raus. Ausgezahltes Geld wird automatisch abgeschlossen.

    Zahlen aus dem Demolauf mit dem echten Kontoauszug im Repo, die Beispielzeilen sind vereinfacht.

    So bleibt jeder Cent sauber

    1. Doppelte Buchführung: jede Buchung ergibt in Summe genau 0
    2. Idempotenz: gleiche Anfrage zweimal, trotzdem nur eine Buchung
    3. Unveränderlich: Fehler werden storniert, nie gelöscht
    4. Outbox: jede Buchung landet garantiert in Kafka
    5. Zugriff nur mit Schlüssel: Shop bucht, Finanzen zahlt aus, Revision liest
    6. Euro und Dollar: jede Währung geht für sich auf 0 auf

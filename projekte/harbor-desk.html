Harbor Desk

Ein Helpdesk als Abo für viele Kunden. Drei Tarife auf einer Codebasis, und ein Ansturm bei einem Kunden bremst die anderen nicht.

Code auf GitHub

So läuft eine Anfrage

  1. Ein Aufruf legt Kestrel Mutual an. Als Enterprise gleich mit eigener Datenbank.

  2. Jeder Tarif hat sein Tempo: Free 20, Pro 100, Enterprise 500 Anfragen pro Sekunde.

  3. Bramble Goods schickt plötzlich 500 Anfragen pro Sekunde.

  4. Bramble bekommt das Tempo seines Tarifs. Norddock antwortet weiter in 6,3 ms.

Das Problem

Ein Helpdesk, den eine Firma als Abo an viele Kunden verkauft. Jeder Kunde bekommt genau das Tempo, für das er zahlt, egal was die anderen tun.

Das Ergebnis

  1. Neue Kunden mit einem Aufruf startklar, Großkunden mit eigener Datenbank
  2. Jeder Tarif bekommt sein Tempo: 20, 100 oder 500 Anfragen pro Sekunde
  3. Ein Ansturm bei einem Kunden: die anderen antworten weiter in 6,3 ms

Probier es selbst

Wähle einen Kunden und starte einen Ansturm. Die anderen bleiben schnell.

Probier es aus: folge den goldenen Hinweisen.

    0Anfragen im Ansturm
    100 %Anfragen der anderen bedient

    Im Browser nachgebaut, mit den Tarifen und Messwerten aus dem echten System. Der echte Code liegt auf GitHub.

    Der Aufbau

    Kleine Kunden teilen sich eine Datenbank und bleiben günstig. Großkunden bekommen eine eigene.

    Entscheidungen

    • 0001

      Geteilte Datenbank für kleine Kunden, eigene für Enterprise

      Kleine Tarife laufen günstig zusammen, Großkunden bekommen Leistung für sich. Beides mit demselben Code.

    • 0002

      Die Regeln stecken in der Datenbank

      Jede Tabelle kennt ihren Kunden. Neue Funktionen sind damit von Anfang an mandantenfähig, ohne Extraarbeit im Code.

    • 0003

      Kunde und Tarif kommen aus dem Login

      Ein signiertes Token sagt bei jeder Anfrage sofort, wer fragt und welcher Tarif gilt.

    • 0004

      Tempo pro Kunde im Arbeitsspeicher

      Ein Zähler pro Kunde und Tarif fängt 95,6 % einer Flut ab, bevor sie die Datenbank erreicht.

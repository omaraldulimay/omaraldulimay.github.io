Das Problem

Ein Helpdesk für viele Firmen auf einer Codebasis. Ein vergessenes WHERE darf nie fremde Tickets zeigen.

Das Ergebnis

  1. 0 Lecks bei 10.000 Zugriffen auf fremde Daten
  2. Selbst eine Abfrage ohne WHERE zeigt nur eigene Zeilen
  3. Eine Firma flutet das System, die anderen bleiben schnell

Probier es selbst

Wechsle die Firma und greif nach einem fremden Ticket. Die Datenbank liefert es nicht aus.

    Im Browser nachgebaut, mit denselben Regeln wie das echte System: Mandant aus dem Token, Row Level Security, 404 für fremde Ids. Der echte Code liegt auf GitHub.

    Der Aufbau

    Die Firma kommt aus dem Token. Den Filter setzt die Datenbank, nicht der Code.

    Entscheidungen

    • 0001

      Pool für kleine Firmen, Silo für Enterprise

      Kleine Firmen teilen eine Datenbank, große bekommen eine eigene. Dafür braucht jedes Silo eigene Verbindungen und eine eigene Migration.

    • 0002

      Row Level Security statt Schema pro Firma

      Der Filter liegt auf jeder Tabelle in der Datenbank. Dafür kostet jede Abfrage etwas und jede Verbindung braucht strenge Regeln.

    • 0003

      Die Firma kommt aus dem signierten Token

      Sie steht nie in der URL und lässt sich nicht fälschen. Dafür bleibt ein Token bis zum Ablauf gültig.

    • 0004

      Limit pro Firma im Arbeitsspeicher

      Ein Eimer pro Firma und Tarif, ohne Datenbank dahinter. Dafür zählt er pro Instanz und nicht exakt über alle.
